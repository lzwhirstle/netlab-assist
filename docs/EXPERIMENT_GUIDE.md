# NetLab Assist 实验使用手册

这份手册按“准备—执行—判定—留证”来写。新同事第一次使用时，先完成第 0 节，不建议直接在复杂拓扑上跑数。

## 0. 两台电脑的通用准备

1. 在 PC1、PC2 各启动一份 NetLab Assist，记录右上角的本机 IP 和六位实验码。
2. 检查网卡只保留本实验所需的有线接口；必要时临时断开 Wi-Fi，避免路由选错。
3. 记录两端 IP、掩码、网关、VLAN、交换机端口、端口 Profile、链路协商速率与 MTU。
4. PC1、PC2 先接同一 VLAN，互相执行一次 TCP 吞吐和连续监控，得到端点基线。
5. 正式对比时固定方向、时长和并发数。每个条件至少跑三轮，不挑最好的一次代替全部结果。

如果连不上，按这个顺序检查：本机 IP → 对端程序是否仍在运行 → 对端实验码 → Windows 防火墙专用网络放行 → 交换机 VLAN/PVID/Profile → 网关和静态路由 → ACL。

## 1. 实验二、三：二层/三层转发吞吐

使用“吞吐测试”。

1. 同 VLAN 跑正向 10 秒、4 流，保存基线。
2. 切换到实验拓扑，保持参数不变再次测试。
3. 分别跑反向和双向同时，观察方向差异；不要只报告双向汇总值。
4. 如果吞吐明显低于链路速率，同时记录两端 CPU、链路协商、丢包/错包与交换机端口统计。

报告中应写：测试方向、并发数、时长、每轮结果、平均值、相对基线变化，以及瓶颈判断依据。

## 2. 实验四：Gateway 三层转发与 NAT

先用“吞吐测试”验证 PC1↔PC2，再用“DNS NAT”观察连接元组。

1. 在 NAT 外侧电脑运行对端节点，内侧电脑输入外侧 IP、实验码和 `18882`。
2. 对比 `client_local` 与 `observed_peer`。二者地址或端口变化说明服务端看到的源元组发生了转换。
3. 同时在正确接口抓包，用时间、源/目的地址和端口把内外侧报文关联起来。

仅凭 Ping 成功不能证明 NAT 已发生；仅凭元组变化也不能代替题目要求的 pcap。

## 3. 实验五：DNS Proxy / Forwarding

使用“DNS NAT”中的 DNS 查询。

1. 关闭浏览器 Secure DNS 或代理干扰，不用网页访问代替 DNS 测试。
2. Proxy 场景把 DNS Server 填为 Gateway/交换机代理地址；Forwarding 场景按题目填写目标 DNS。
3. 使用相同域名、记录类型和相近时间分别跑 UDP 与 TCP。
4. 记录 `query_transaction_id`、`source_port`、`response_bytes`、回答地址和耗时，并与抓包对应。

如果返回 `rcode` 非 0，先判断域名、上游 DNS、路由和策略，不要直接归因于 Proxy 功能。

## 4. 实验六：DHCP Server & Interface Relay

本工具不充当 DHCP Client 或抓取 DHCP 四步交互，但“连续监控”可以补充验证地址切换后的业务恢复。

1. DHCP 获取与 Relay 仍使用系统 `ipconfig/ifconfig`、Controller/CLI 和 Wireshark 验证。
2. 地址获取成功后，把目标设置为对端 NetLab Assist 的 `18882`，开始连续监控。
3. 执行续租、端口/VLAN切换或管理 VLAN 切换，记录中断和恢复时间。

报告必须保留 Discover、Offer、Request、ACK 与 Relay 地址字段；连续监控结果只能作为业务层补充证据。

## 5. 实验九：LACP

使用“吞吐测试”的 4/8/16 流和“连续监控”。

1. 先确认聚合组 Up，成员口速率、双工和 VLAN 配置一致。
2. 多流吞吐运行时同时读取每个成员口的字节/包计数，验证哈希分担。
3. 保持连续监控，拔掉一个成员口，记录业务是否中断及恢复时间；再恢复成员口观察重加入。

总吞吐增长不等于每条会话带宽叠加，也不能替代成员口计数器证据。

## 6. 实验十：ACL

使用“ACL验证”。

1. 策略下发前跑一遍矩阵并导出，证明目标服务本来可用。
2. 下发 ACL 后用完全相同的矩阵再跑一遍。
3. `connected` 可作为 TCP 放行证据；`refused` 只能说明到达主机但服务未监听，应先修复基线。
4. `timeout/no_reply` 与阻断相符，但还要排除路由、ARP、主机防火墙和服务异常，并查看 ACL 命中计数。

## 7. 实验十一：IGMP Snooping / IPTV

使用“组播 IPTV”。接收端必须先启动，发送端后启动。

1. 接收端选择“接收频道”，设置相同组播地址和端口。
2. 发送端选择“发送频道”，建议先用 5 Mbps、30 秒。
3. 记录接收码率、丢包、乱序、加入和退出时间。
4. 在交换机同时检查 IGMP Group 表与加入/未加入端口计数器。

工具使用的是可量化测试流，不是视频编码器。需要主观画面体验时仍配合 VLC。

## 8. 实验十三：RSTP/链路收敛

使用“连续监控”。

1. 目标填对端 NetLab Assist IP，端口填 `18882`，间隔建议 `0.1–0.5` 秒。
2. 监控稳定后执行断链、恢复或主备路径切换，并手工记录动作时刻。
3. 导出结果，关注状态变化、最长中断和可用率；与 RSTP 角色、端口状态和日志时间对应。

TCP 监控包含操作系统调度和重试影响，适合比较相同条件，不应被描述为专业仪表级收敛精度。

## 9. 归档命名建议

`实验编号_场景_方向或阶段_日期_执行人`

例如：`Exp10_AfterACL_PC2-to-Gateway_20260904_LiangZheng.md`

同一 Case 目录建议包含：

- NetLab Assist 导出的 Markdown 与原始 JSON
- 拓扑和 IP/VLAN 表
- Controller/CLI 配置与状态截图
- 端口计数器前后值
- Wireshark pcap 与关键帧号
- 异常现象、控制变量、复测结果和未验证项
